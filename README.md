# pi-crofai-provider

[![npm version](https://img.shields.io/npm/v/pi-crofai-provider.svg)](https://www.npmjs.com/package/pi-crofai-provider)

CrofAI provider for the [pi coding agent](https://github.com/earendil-works/pi-coding-agent) — hard fork of [`pi-crofai`](https://www.npmjs.com/package/pi-crofai).

## Which provider to use

| Provider | Protocol | When to use |
|---|---|---|
| **`crofai`** | `/v1/chat/completions` | **Default. Use this.** More mature in pi; supports `deferredToolsMode: "kimi"` for faster first-token on tool-heavy sessions with Kimi models. |
| `crofai-responses` | `/v1/responses` | Niche. Only if you specifically need the Responses API (`reasoningSummary`, `serviceTier`). Less tested in pi. |

Both share the same 16-model catalog and the same API key.

## Install

```bash
# From npm (recommended):
pi install npm:pi-crofai-provider

# Keep it updated:
pi update npm:pi-crofai-provider

# Or straight from this repo (latest main):
pi install git:github.com/dawidmachon/pi-crofai-provider

# Dev: local checkout, one session:
pi -e /path/to/pi-crofai-provider
```

Then restart pi or type `/reload`.

## Setup

```bash
export CROFAI_API_KEY="your_key_here"
```

Or: `pi` → `/login` → **Use an API key** → `crofai` (or `crofai-responses`) →
paste key. CrofAI is API-key auth only, so it appears in that section — there
is no account/OAuth flow.

Providers always appear in `/login`; their models show up in `/model` as soon
as auth exists — no restart needed. Live catalog refresh activates per provider
once it is configured (run `/reload` once after your first `/login`).

## Hard-fork fixes vs upstream

1. **Vision detection** — upstream's hand-curated list had 5 phantom entries and missed `deepseek-v4-flash-vision-exp`. This fork infers vision from model-id patterns.
2. **Fetch timeout** — 5 s hard cap on `/v1/models` so a slowCroft.ai doesn't block extension load.
3. **NaN guard** — malformed pricing fields fall back to 0 with a warning instead of silent corruption.
4. **`/reload` support** — uses pi's official `refreshModels` callback; new CrofAI models appear after `/reload`, no restart needed.
5. **Zero-latency startup** — an embedded catalog snapshot (`models.snapshot.json`) registers instantly, even offline; the live catalog is revalidated in the background and hot-swapped.
6. **Evidence-based curation** — `curations.json` applies measured per-model corrections (vision, thinking levels, honored token field) on top of API flags, generated by the probe script.
7. **Usage footer** — session cost summed locally from turn usage (no extra requests); credits/requests balance fetched throttled (≥90 s and ≥3 turns apart).
8. **Responses API** — registers both `/v1/chat/completions` and `/v1/responses` providers from the same catalog.
9. **No phantom refresh errors** — unconfigured providers never trigger `/model` refresh errors: live catalog refresh attaches only once a provider is configured (env key or stored credential).

## Development

```bash
npm run check                                            # typecheck + selfcheck
npm run update-models                                    # regenerate models.snapshot.json from the live API
npm run probe-models -- --models kimi-k3,glm-5.3         # E2E capability probes (spends credits)
npm run probe-models -- --checks maxtokens --models kimi-k3
```

`probe` measures what the API only claims: whether a 1×1 image is accepted
(vision), which `reasoning_effort` levels a model actually accepts, and which
token-cap field (`max_tokens` vs `max_completion_tokens`) is honored. Results
go to `curations.json` (applied by the extension at runtime) and
`probe-report.md` (verbatim evidence: request params, HTTP status, usage
counts, error bodies). Run it before releases when the catalog changes.
